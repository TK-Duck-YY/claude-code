## 步驟 7 — 更新條文內容

先把現行條文全文抓下來存成 `q2_articles/<法規編碼>.json`（`{"條號": "全文"}`），再由
`ohs_apply_articles.py` 統一寫入 Excel。**不要讓多個程序同時寫同一份 xlsx。**

條文量大時（如本季 151 條、約 3.6 萬字）建議每 2～3 部法規分派一個子代理抓取，
子代理只負責產出 JSON、不碰 Excel。子代理各自使用內建瀏覽器，結束時關閉自己開的頁面；
若內建瀏覽器無法同時多開頁面，改為序列抓取。

### 抓條文（換行結構是重點）

用內建瀏覽器執行 `references/browser-fetch.md` §4 的 `getArts`。
關鍵：必須逐行取 `div[class^="line-"]`，`innerText` 在 DOMParser 文件會退化成 `textContent`，換行全失。

**驗證**：凡條文同時含「一、」與「二、」者，值必須含 `\n`；每條長度要與內建瀏覽器端記錄一致（截斷是無聲的）。

### 寫入規則

| 情況 | 處理 |
|---|---|
| 條號已存在、單列 | 舊文與新文做 `difflib` 字元級 diff：`equal` 黑字無底線、`replace/insert` 紅字加底線 |
| 條號已存在、跨多列 | **以原各列首行為錨點**切回同列數（見下） |
| 條號不存在（增訂） | 依條號順序 `insert_rows` 插在下一條之前，樣式複製相鄰列，整列紅字加底線 |
| 刪除條文 | `C` 欄寫紅字「（刪除）」 |
| 全文修正 | 該法規所有條文都跑上述流程；比對後無差異者維持黑字 |

### 跨多列條文：依錨點切分（`split_by_anchors()`）

**不要用「分項數 == 列數」判斷**——法條分項數與 Excel 拆列方式無關，幾乎永遠不符。
正確做法是拿**原檔各列的首行**當錨點，在新條文中找同一個切點：

- 型態 (a)：只有首列有內容、後續列是空白列（如道交規則第 3 條）→ 全文寫首列，其餘維持空白
- 型態 (b)：每列都有內容，在特定款次切開（如第 60 條列 98 從「（八）」起、第 112 條列 168 從「十三、」起）
  → 取各列首行去空白後的前 10 字當 probe，在去空白的新條文中定位，依位置切段
- 錨點找不到或順序錯亂 → 才退回「全文寫首列」並列入人工確認

**驗證**：把該條各列文字接回來，去空白後應與網站原文完全相同。

**必踩的坑**：
- `load_workbook()` 一律加 `rich_text=True`，否則前一支腳本寫的紅字會被洗掉
- 掃描 B 欄條號時用 `^\d+(-\d+)?$` 過濾，否則第 5 列表頭「條文」會被當成條號
- 清空儲存格前先判斷 `isinstance(cell, MergedCell)`
- log 不要直接寫進 OneDrive 同步資料夾（flush 會 deadlock）：先寫 `tempfile.gettempdir()`，
  `atexit` 時 `shutil.copy2` 回 `logs/`

| 群組 | 檢核內容 |
|---|---|
| 1 | 三個原始檔大小與基準值相符（未被修改） |
| 2 | 三個 `{TAG}` 產出檔存在 |
| 3 | 目錄：工作表數、`K3` = 季末日、底線 79 格、紅字法規數 == 異動數、E/F 日期相符 |
| 4 | 各異動表 `A4` 為 CellRichText、全紅、含標楷體 |
| 5 | **每一條條文與 `q2_articles/*.json` 去空白後逐字比對** |
| 6 | 條文儲存格全為 CellRichText（未被壓成純文字） |
| 7 | 各表 B 欄條號遞增（增訂列插入位置正確） |

## 每季固定要問使用者的事

這些無法從檔案推斷，且會影響結果：

1. **「修正發布全文」的法規**：全文重寫後只標真正改動的段落／整表標紅／跳過（115Q2 選第一項）
2. **分階段施行時 F 欄填哪個日期**：最早生效日／主要施行日／加註（115Q2 選最早生效日）
3. **新訂子法**是否要新增目錄列與整張條文工作表（115Q2 選不查）
4. **未異動工作表的往季紅字**是否一併還原（115Q2 尚未裁示，維持不動）
